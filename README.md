# Mini AI Business Intelligence Assistant

An AI-powered sales analytics application that lets business users ask questions about sales data in natural language and receive answers backed by SQL queries.

Built as part of the **AI-Assisted Development Challenge for Graduate Engineer Trainee (GET) selection**.

## Features

- **Natural-language analytics:** Ask questions about revenue, products, regions, sales channels, and monthly trends.
- **AI-powered SQL generation:** Uses Google's Gemini API to translate business questions into SQL.
- **SQL validation:** Uses SQLGlot to validate generated queries before execution.
- **Database-backed results:** Stores sales transactions in SQLite and calculates results using SQL.
- **Interactive dashboard:** Streamlit interface with suggested questions, result tables, charts, and CSV downloads.
- **Data-quality handling:** Flags missing or invalid values and records requiring review.
- **REST API:** FastAPI backend with structured JSON responses and error handling.

## Prerequisites

- Python 3.11 or later
- A Google Gemini API key
- Internet access for Gemini API requests

SQLite is accessed through Python's built-in `sqlite3` module; a separate SQLite server installation is not required.

## Installation and Setup

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
cd YOUR_REPOSITORY
```

Replace the repository URL with the actual GitHub URL.

### 2. Create a virtual environment

**Windows:**

```bash
python -m venv .venv
.venv\Scripts\activate
```

**macOS/Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install -r requirements.txt
```

### 4. Configure the Gemini API key

Copy `.env.example` to `.env` and add your own API key.

Example `.env`:

```dotenv
GEMINI_API_KEY=your_actual_api_key
GEMINI_MODEL=your_supported_model_name
```

Use a model name supported by your Google AI API account and the SDK version installed in the environment.

**Security:** Never commit `.env` or expose your API key in source code, screenshots, logs, or public repositories.

### 5. Import the sales data

Ensure the supplied CSV is present at `data/sales.csv`.

Run:

```bash
python -m database.import_data
```

This creates or refreshes the SQLite database and imports the sales records according to the data-cleaning and validation logic implemented in the importer.

Run the import command again only when you intend to rebuild the database from the CSV.

## Running the Application

The application requires two running processes.

### Terminal 1: Start FastAPI

```bash
uvicorn main:app --reload
```

API base URL:

`http://127.0.0.1:8000`

Interactive API documentation:

`http://127.0.0.1:8000/docs`

### Terminal 2: Start Streamlit

Activate the virtual environment in the second terminal, then run:

```bash
python -m streamlit run app.py
```

Open:

`http://localhost:8501`

Keep both processes running while using the application.

## Example Questions

The application is intended to support analytics such as:

- What is the total revenue?
- Which product generated the highest revenue?
- What is the monthly revenue trend?
- Which region generated the highest sales?
- How did revenue change between two months?
- What is the total revenue for each product category?
- Which sales channel has the most transactions?

Supported questions depend on the database schema and the SQL generated by the AI model.

## API Usage

**Endpoint:** `POST /api/ask`

Example request:

```json
{
  "question": "Which product generated the highest revenue?"
}
```

Example response structure:

```json
{
  "question": "Which product generated the highest revenue?",
  "sql": "SELECT ...",
  "columns": ["product", "revenue"],
  "rows": [
    {
      "product": "Example Product",
      "revenue": 125000
    }
  ],
  "row_count": 1
}
```

The example response illustrates the response format; the actual SQL and values depend on the dataset and query.

## Data Quality and Revenue Calculation

The importer identifies data-quality issues such as missing prices, invalid dates, invalid numeric values, and duplicate transaction identifiers.

Records flagged for review are retained according to the implemented data-handling policy, and flagged rows may be exported to `data/rejected_rows.csv` for inspection.

Revenue is defined as:

```text
Revenue = quantity * unit_price - discount_amount
```

For revenue analysis, the intended business rule is to include completed transactions and exclude records with missing or invalid fields that affect the calculation. The exact filtering behavior is determined by the generated SQL and backend implementation.

## Security and Reliability

- Generated SQL is validated before execution.
- Destructive SQL statements are intended to be blocked.
- Database queries use a read-only SQLite connection.
- API errors are returned as structured HTTP responses.
- API credentials are supplied through environment variables.

SQL validation is a safeguard, not a complete security guarantee. Before production deployment, query validation, execution limits, database permissions, and error handling should be reviewed and tested thoroughly.

## Testing

Run the automated tests with:

```bash
pytest -v
```

Tests should cover:

- Valid analytics queries
- Invalid or unsupported questions
- SQL validation and blocked destructive statements
- Empty inputs and error handling
- Data-quality edge cases

Only tests actually implemented and passing should be reported as completed.

## Known Limitations

- Results depend on the quality of AI-generated SQL.
- Unsupported questions may not be answerable from the available schema.
- Gemini requests require network access and may experience latency or API errors.
- SQLite is suitable for this small assessment but is not designed for every concurrent, large-scale production workload.
- The local database is generated from the supplied CSV and must be initialized before running the application.
- The application has not necessarily been hardened for public production use.
